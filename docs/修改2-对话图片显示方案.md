# 修改 2：对话中发送图片不显示 — 方案

- 日期：2026-11-22
- 现象：用户在输入框附图片发送后，对话里的用户消息气泡只显示文字，看不到图片。
- 状态：**已按方案 B 实施（2026-11-22）**

---

## 1. 先分清两件事

“图片不显示”可能是两层问题，修之前要分开：

| 层 | 问题 | 现状 |
|---|---|---|
| **UI 显示** | 图片已经发出去了，但用户消息气泡没有渲染图片 | **确定存在**（代码原因见下） |
| **模型是否收到** | 当前模型不支持图片时，主进程会把图片转述成文字再发给 pi | 逻辑存在；未配视觉服务时只给一句占位提示 |

所以“气泡里没图”不等于“模型没收到图”。修 UI 的同时，最好把“模型是否真的看到图”也显示清楚。

---

## 2. 根因（代码定位）

### 2.1 发送时图片没有进入消息列表

`apps/renderer/src/App.tsx`：

- 用户消息类型：

```ts
| { kind: "user"; text: string; failed?: boolean; id?: string }
```

没有图片字段。

- 发送时（约 1045 行）：

```ts
setMessages((prev) => [...prev, { kind: "user", text, id: msgId }]);
```

`pendingAttachments` 只放进了 `pendingUser`（用于失败回填），**没有放进消息**。

- 渲染用户消息（约 2141 行）：

```tsx
<div className="bubble">
  {m.text}
  {m.failed && <span className="msg-failed">未送达</span>}
</div>
```

只输出 `text`，没有 `<img>`。

### 2.2 历史恢复只保留文字

`apps/renderer/src/tool-rebuild.ts` 的 `messagesFromAgent`：

```ts
const text = textOf(m.content);
if (text) out.push({ kind: "user", text });
```

`textOf` 只挑 `type === "text"` 的 block（App.tsx 195 行），**image block 被丢掉**。

因此：

- 发送后当前会话不显示；
- 切走再回来（`getMessages` → `messagesFromAgent`）更不显示，因为历史里图片也被过滤了。

### 2.3 图片其实已经处理过

`apps/desktop/src/main/index.ts` 的 `pi:prompt`：

- `saveAttachment(img.data, mimeType)` 把原图写到 `<workspace>/.omcp/attachments/`；
- 模型支持图片 → `rpc.request({ type: "prompt", message, images })`；
- 不支持 → `transcribeImages()` 转述后拼进文本。

也就是说，**图片文件在，发给 pi 的路径也在**，只是前端消息没有引用它。

---

## 3. 方案对比

### 方案 A：只修发送时显示（最小）

- `Msg` 的 user 加 `attachments`；
- 发送时把 `pendingAttachments` 放进消息；
- 气泡渲染 56px 缩略图（复用现有 `.attach` 样式）。

优点：改动最小，直接解决截图问题。
缺点：切会话/重启后图片消失；纯文本模型历史也消失。

### 方案 B：发送时显示 + 历史 image block 恢复（推荐）

在 A 的基础上：

- `messagesFromAgent` 对 user content 保留 `type === "image"` 的 block；
- `RebuiltMsg` / `Msg` 带上 attachments；
- 渲染时显示缩略图；点击打开大图（应用内 overlay）。

覆盖：

- 模型支持图片：发送后、切换会话、重启后都能恢复；
- 纯文本模型：发送后当前会话显示；切换会话后无法从 pi 历史恢复（因为 pi 历史里只有转述文字，没有 image block）。

优点：改动中等，覆盖主流程；不依赖额外持久化。
缺点：纯文本模型的历史图片仍会丢。

### 方案 C：完整附件索引（最大）

在 B 的基础上：

- 发送时把 `msgId` + 附件路径写入 `.omcp/attachments/index.json`（或 session meta）；
- 历史恢复时按 `msgId` / 顺序关联；
- 纯文本模型也能恢复；
- 增加清理策略（按会话/时间）。

优点：完整。
缺点：改动大；msgId 与 pi 历史顺序在 fork/queue 下不一定稳定；需要定义存储格式与清理。

**推荐：先做 B。** 纯文本模型的历史恢复（C）等确认需求后再做。

## 4. B 的实施步骤（待批准）

### 4.1 类型

`App.tsx`：

```ts
type UserImage = { id: string; data: string; mimeType: string };

| { kind: "user"; text: string; attachments?: UserImage[]; failed?: boolean; id?: string }
```

`tool-rebuild.ts` 的 `RebuiltMsg` 同步加 `attachments?`。

### 4.2 发送

```ts
setMessages((prev) => [
  ...prev,
  { kind: "user", text, id: msgId, ...(pendingAttachments.length ? { attachments: pendingAttachments } : {}) },
]);
```

`pendingUser` 仍保留附件，失败回填逻辑不变。

### 4.3 渲染

用户气泡：

```tsx
{m.attachments?.length ? (
  <div className="msg-attachments">
    {m.attachments.map((img) => (
      <button key={img.id} onClick={() => openPreview(img)}>
        <img src={`data:${img.mimeType};base64,${img.data}`} alt="图片" />
      </button>
    ))}
  </div>
) : null}
<div>{m.text}</div>
```

- 复用 `.attach` 的 56px 缩略图样式；
- 图片在文字上方（聊天软件习惯）；多图横向换行；
- 点击打开应用内大图 overlay（可复用现有 overlay 样式）。

### 4.4 历史恢复

`messagesFromAgent` 对 user：

```ts
const text = textOf(m.content);
const images = m.content
  .filter((b) => b.type === "image")
  .map((b, i) => ({ id: `hist-${i}`, data: b.data, mimeType: b.mimeType }));
if (text || images.length) out.push({ kind: "user", text, ...(images.length ? { attachments: images } : {}) });
```

### 4.5 缩略图与内存

- 第一阶段直接渲染原图 base64（现有附件预览就是这样），`<img>` 显示 56px；
- 如果多图/大图导致滚动卡，再加 canvas 缩略图（160px）到 `attachments[].thumb`；
- 不在消息里复制 base64，引用同一个字符串。

### 4.6 主进程（第一阶段可选）

- 现在 `saveAttachment` 的返回值被忽略；
- 可选：`pi:prompt` 返回附件路径，气泡提供“在文件夹中显示”（`shell.openPath`）；
- 不在本次必须范围内。

## 5. 验收标准

1. 发送一张图：用户气泡**立即**显示缩略图，文字与图片布局正常，无溢出。
2. 多图：缩略图横向排列/换行，不撑破气泡。
3. 切换会话再回来（模型支持图片）：图片仍在。
4. 纯文本模型：当前会话显示缩略图；模型收到转述；视觉服务未配置时有明确提示。
5. 发送失败：消息标“未送达”，输入框回填文字 + 图片。
6. 点击图片：应用内大图预览，可关闭。
7. 无图消息布局不变。
8. `pnpm --filter @oh-my-coding-pi/desktop typecheck` 与 build 通过。

---

## 6. 风险与边界

| 风险 | 说明 | 处理 |
|---|---|---|
| base64 内存 | 单张最大 4MB，最多 5 张；列表渲染原图可能占内存 | 先直接渲染；卡则加缩略图 |
| 会话体积 | pi 历史本身会保存 image block，前端不额外持久化 | 不在 `.omcp` 重复存 base64（除非做 C） |
| 纯文本模型历史 | pi 历史只有转述文字，没有 image block | 本次接受“历史不显示”；需要则做 C |
| 图片格式 | 目前支持 png/jpeg/webp；gif 等可能显示但模型不支持 | 保持现有上传限制 |
| 隐私 | 原图已写入 `<workspace>/.omcp/attachments/` | 保持现有目录；后续可加清理 |
| 大图预览 | data URL 直接打开可能被 CSP/窗口限制 | 用应用内 overlay，不用 `window.open` |
