## 1. 安全

1. **权限不是安全边界**。应用与 pi 以当前用户权限运行；同用户进程可绕过应用直接读写文件（ADR-004）。权限门拦的是模型/手滑，不是恶意程序。
2. **脚本内删除只做启发式检查**。P4.0 起会读脚本前 4KB，命中删除/子进程模式就要求审批；但超出 4KB、动态拼接、编译后的程序仍查不出来。
2.1 **审批的覆盖范围是明确的**（D1，2026-11-15 决策）。审批门覆盖两类动作：
   ① `run_code` 工具执行；② 通过 bash 调用脚本时，对脚本前 4 KB 做危险模式检查（删除、子进程等）。
   直接写在 bash 命令里的代码（例如 `python -c "..."`、`Rscript -e`）按 bash 规则处理，**不触发 `run_code` 审批**。
   这是被接受的设计边界，不是遗漏：把这类写法逐个加进 `commands.ask` 只会抬高弹窗频率，
   仍可用 `powershell -c`、`node -e` 等方式绕过，反而更容易让人误以为已经隔离。
3. **没有沙箱/容器**。容器化留到 v1.1 评估。
4. **只读模式下笔记本默认阻断，但可手动放开**。`readonlyNotebook=true` 后只读仍可执行 cell，这是刻意的逃生口。
5. **只读模式下 run_code 直接拒绝**，不做代码静态分析（D6）；需要“能算不能写”要等容器或 IO 拦截。
6. **审批超时按拒绝处理**（默认 120 秒）；用户离开时，长时间任务会被审批门挡住。
7. **项目级资源默认不加载**：`.pi` 设置、项目扩展、`.agents/skills` 需要显式勾选“信任本项目”；
   默认传 `--no-approve`，即使本机全局设了 `defaultProjectTrust: always` 也不生效（ADR-036）。
7. **安装包为自签名**。签名者显示 `CN=oh-my-coding-pi self-signed`，但证书不在受信任根，SmartScreen 仍提示“未知发布者”（ADR-032）。
8. **卸载会删程序文件与快捷方式，但不删用户数据**：`%APPDATA%\oh-my-coding-pi` 里的
   `settings.json`、`secrets.json`、`sessions/`、`memory/`、`pi/` 保留下来（Electron 默认行为），
   重装后会接着用。需要彻底清理得手动删这个目录。
8.1 **卸载可能被文件占用阻塞**。占用者通常是其它索引工作区的程序（本机为 DAWN Science），
   不是卸载器缺陷。卸载会重试删除，仍失败则登记 HKCU RunOnce，下次登录清理；
   极端情况下残留会存在到那次登录为止。改名前的实测（无占用）卸载 11 s、目录与注册表项均清干净。

## 2. 功能

1. **设置页已覆盖常用项**（模型/预算/Python 路径/策略路径/更新源）。模型密钥由本应用管理：
   存在本机安全存储（safeStorage），注入 pi 时**同时**使用 pi 官方环境变量名（内置 provider）
   与 `OMCP_KEY_<ID>`（自定义 provider）；`models.json` 只写 `$OMCP_KEY_<ID>` 引用，不落明文。
1.1 **不接管 pi 的 `/login` 与 OAuth**：登录态仍由 pi 的 `auth.json` 负责，应用只做"有没有凭据"的只读探测。
1.2 **发送前预检只判"有没有凭据 / 地址合不合法 / 模型是否存在"**，不联网验证密钥有效性；
   密钥是否真的可用，要等第一次真实请求（或点"测试连通"）。
2. **树只能 fork，不能跳转**。pi RPC 没有 navigate 命令。
3. **会话目录在工作区**（`<ws>/.omcp/sessions`），换机器需手动带走。
3.1 **笔记本只存 cell 代码**：文本与图像输出不落盘，重开需重跑（界面工具栏已标注）。
4. **没有自动更新**，升级需重新下载安装包。
4.1 **更新检查只支持公开仓库**。请求不带任何凭证，私有仓库会返回 401/403，界面提示“仓库不可访问”并给手动下载入口；
    不做 token、不要求把私有仓改公开。失败按 auth / not_found / ratelimit / timeout / network / parse 六类提示（D2）。
5. **没有多窗口/多工作区**。一个应用实例一个当前工作区。
5.1 **界面布局**：左栏常驻、可拖宽（240–420），不再折叠；右坞可拖宽（280–520），
    关闭后不保留图标条，用顶栏「面板：X」重新打开。宽度、右坞开合与当前面板落盘（`omcp.global.*`）。
    旧键 `omcp.global.layout-mode` 与 `omcp.global.sidebar-collapsed` 只在升级后第一次读取时迁移/删除。
    分隔条可聚焦，←/→ 每次 16px；快捷键 Ctrl+J / Ctrl+Alt+1–4；**Ctrl+B 与 Ctrl+1–4 已空置**。

### 2.1 内核启动与执行（2026-11-16 起）

1. 启动不再调 jupyter_client 的 `wait_for_ready`：改为**先订阅 iopub、再每 250 ms 换一个新 `msg_id` 重问 `kernel_info`**，shell 回复与 iopub 第一声（`iopub_welcome` 或握手的 `status`）都到才算就绪，预算 20 s。
   旧路径在 Windows + pyzmq 27 + jupyter_client 8.10 上会 20 s 超时（实机自测 §7.3 L2）。
2. 就绪前不发执行请求；执行完成只认 **parent 等于本轮** 的 `status:idle`。shell 已回 `execute_reply` 而 2 s 内没有 idle 时，降级收口并输出
   `[警告] 输出通道(iopub)未响应…`——**这时输出可能不全**，需重跑该 cell，不要把它当成正常结果。
3. 启动失败会先杀内核进程再关通道，并把内核 stderr 末尾 20 行随错误抛出；不再有“末尾为空”的 `KernelError`。
   连续失败不再堆积内核进程（旧版会泄漏，实机自测 §8 记了 7 个）。
4. R 的 argv 按启动器选：`Rterm` 必须带 `--args`，`Rscript` 必须不带；启动后预载 stats/graphics/grDevices/datasets/methods。
5. 审计新增 `outcome`（ok / durationMs / status / errorClass / kernelPid）：`scope:"outcome"` 的记录才代表“跑完了没有”，
   与 `decision:"allow"` 的放行记录区分开。

### 2.1.1 启动竞态与端口等待（2026-11-17 起）

1. 建客户端通道前会**等内核把 shell/iopub 端口 bind 完**（通常 <1 s；可用 `OMCP_KERNEL_PORT_WAIT_S` 调整，默认 10 s）。
   原因：本机 pyzmq 27.2 / libzmq 4.3.5（Windows）上，`connect()` 早于 `bind()` 的 socket 会停在
   `CONNECT_DELAYED` 且不再重试——实机报告里 13 次只成 1 次，加这一步后 10/11。
2. 内核在端口就绪前退出（例如缺 ipykernel）会**立刻**失败并带出它的 stderr，不再空等 10 s。
3. 握手仍失败时会重建一条通道再试一次（8 s 预算）；二次失败才回收内核。
4. 内核启动时那句 `Kernel is running over TCP without encryption` 是**正常警告**，不是失败原因。

### 2.2 产物面板（2026-11-16 起）

1. **产物 = 账本 + 约定目录**。账本落在工作区 `.omcp/artifacts.jsonl`：每次工具结束记一条
   「哪个工具、哪个调用、产出了哪些路径」。`write` / `edit` 能从入参精确取到路径；
   `bash` / `run_code` 无法枚举，记为 `unknown`。
2. **不知道就说不知道**：`unknown` 次数会显示成「另有 N 次运行产出未知」，不会画成「没有」。
3. 约定目录 `figures/`、`results/` 每次刷新扫一遍（深度 ≤ 5、最多 400 个），补上脚本写出来的文件；
   账本里已有的路径不重复列出，归属以账本为准。
4. 账本里有、磁盘上没了 → 显示「已不存在」，条目保留，不静默删除。
5. 工作区只读时记账静默失败（不影响工具结果）；面板不做科学结论解读，只回答「产出了什么文件」。

### 2.3 产物预览（2026-11-17 起）

1. 点产物在**产物面板内**预览，不跳「文件」页签；文件页签的目录、滚动、选中不受影响。
2. 预览复用只读的 `readFile`：图片原图、CSV/TSV 表格、Markdown 渲染、其余文本按原文；
   超过读取上限或二进制只给提示 + 「在文件页签打开」。
3. `← 列表` 或 `Esc` 返回，列表滚动位置保留；预览期间文件被删会标「已不存在」但不闪退。
4. PDF 不预览（要处理不可信文档与内存上限，另开一项）。

### 2.4 待发队列（2026-11-17 起）

1. 运行中按 `Enter` = **排队**（pi 的 `followUp`），`Ctrl/Cmd+Enter` = **立刻转向**（`steer`）。
2. 队列以 pi 的 `queue_update` 为准，界面只做投影；不要指望界面自己维护一份"更准"的队列。
3. 「取回」调 `clear_queue`，把待发文本原样放回输入框；「调整方向」= 取回全部 → 目标条转向、
   其余按原顺序重投（pi 的队列没有单条 id）。
4. 「新增会话」在**这一轮结束后**执行；运行中切会话会丢掉当前轮，所以不做立即切换。
5. 「到坞里问」未实现：右坞没有对话容器。

### 2.5 工具调用组（2026-11-17 起）

1. 工具组**默认收起**：组头只写「跑了 N 条命令」+ 失败数 + 总耗时，点开才看逐条。
2. 运行中自动展开看进度；**跑完一律收起**（修改 4 D1-A）。
3. 工具调用是转写的一部分：从会话里的 `toolCall` 块与 `toolResult` 消息重建，
   切会话、翻历史、开始下一段对话都还在；重建拿不到起止时刻时不显示耗时（不编）。
4. 单条工具（不成组）仍用卡片，报错默认展开。

### 2.6 会话标题（2026-11-17 起）

1. 标题由首条用户消息派生：去 Markdown、`@` 路径折叠、URL 只留域名、最多 24 字。
2. 没说过话的会话没有标题（列表回落到 ID 前 8 位）；旧会话在列表加载时懒回填一次。
3. 手动重命名后打 `renamed` 标记，不再被自动标题覆盖；清空标题会重新生成。
4. 标题是**启发式**，不保证概括准确；模型生成标题（DAWN 的主路）留作后续可选。

## 3. 稳定性与测试

1. `auto_retry` 映射未做真实故障注入（429 未人为制造）。
2. 3s 硬重启未单独压力测试。
3. 审批弹窗的“取消/断线”路径有实现，但只在杀 pi 的场景下隐式覆盖，没有独立用例。
4. 持久授权的过期清理只在读取时过滤，没有后台定时任务。
5. 只在 Windows 10/11 x64 验证；macOS/Linux 未测。
6. **内核执行是串行排队**（P2-01）：同一语言最多 4 段在等，超了直接拒并提示；排队仅发生在主进程，
   单元格之间不会并发执行（内核本来也只能一段一段跑）。中断只影响当前那一段，排队的不自动清空。

## 5.0 技能

1. **技能是指令注入面**：项目里的 `SKILL.md` 可写步骤诱导模型执行命令；默认不加载项目技能（ADR-036）。
2. **不做在线安装与来源校验**：只读 `.agents/skills/`，不做 GitHub 安装、不记录来源（ADR-037）。
3. **技能不做 token 上限**：注入多少由 pi 决定；技能很多时描述会全部进上下文。
4. **只看描述不读正文时不落技能审计**：审计只记录“读了 SKILL.md”或“调了 use_skill”。

## 5.0.1 视觉

1. **图片会离开本机**：启用视觉服务后，粘贴的图片与 `run_code` 生成的图会发到该端点。
2. 转述可能失真：只描述可见内容，数字仍应回看原图。
3. 单条消息最多 4 张图；转述 30 秒超时、不重试。
4. 附件存 `.omcp/attachments/`，没有自动清理。

## 5.0.2 路线与方案期

1. **方案期默认关闭**，会话级；切会话/切工作区回到未批准。
2. 方案期内 **bash/powershell 整件拒**，只读工具才放行——看数据请先退出方案期。
3. **批准绑定的是内容**（P1-01）：批准时记下计划文件 sha256，之后每次非只读操作前复核；文件被修改/删除/读不出来就撤销批准、退回只读（`plan:drift`）。
   它只做“**发现并失效**”，不做“被改后恢复成批准时的版本”——后者需要备份与写回，未实现。
4. 路线表是人写的，不做自动推断；产物路径是否“缺失”只检查文件存在，不校验内容。

## 5.1 更新与运维

1. 检查更新用 GitHub 匿名 API，受 60 次/小时限流；无 token。
2. 不自动安装、不提示“提醒频率”，v1 手动点。
3. provider 变更会重启 pi（约 1 秒），进行中的回合中断。
4. 诊断包是 store 模式 zip（不压缩），文本内容，体积几十 KB。

## 5.1.1 安装包（内置 pi 后）

1. 安装包约 **124 MiB**，安装后约 **406 MB**，安装耗时约 **69 秒**（1.1 万个小文件）。
2. 安装路径超过 200 字符会被拒绝（内置依赖路径较深）。
3. 内置版本随应用发布；`pi update` 不会更新内置副本。

## 5.2 pi 运行时

1. **版本护栏只警告不拦**：`--version` 与 `.pi-version` 不一致时报告警告，仍可继续使用。
2. **默认共享 `~/.pi/agent`**：改系统 pi 的设置会影响本应用；需要隔离时在设置里开“独立配置目录”（要重新登录）。
3. **内置与系统 pi 可能同时存在**：诊断包会分别记录，排障时先看“来源”。

## 7. 已知不可用场景

- 处理未发表数据/敏感数据：本机直跑、无沙箱，权限只能防误操作。
- 需要审计合规：本地 JSONL 审计可被同用户进程删除/改写，不构成合规证据链。
- 需要 macOS/Linux：未测。
8. **三档权限不是沙箱**：完全访问只跳过询问，硬拒清单仍生效；`run_code` 里的代码不过这道门。
9. **压缩线是推算值**：pi 只报 tokens/上限，仪表里的 `compactAt = 上限 − 16384`（pi 默认 reserveTokens）；
   pi 设置里改过 reserveTokens 时会偏，界面已标注“按默认值推算”。
10. **浏览器插件不是万能抓取器**：复用系统 Edge/Chrome 的无头模式，部分站点（Cloudflare 等）会拦；
    不做绕过，失败原因原样回给模型。
11. **浏览器是共享的**：多段对话共用一台浏览器与标签表，`browser_close` 会影响所有对话；
    浏览器服务随主进程退出关闭，主进程崩溃时依赖 Chromium 父进程退出自清。
