## 1. 内核：从“起不来”到“起得来、说清楚”

这一版最大的一块是内核。上一版在另一台机器上实测：Python 与 R 手工直连都是 7/7，
但应用里的 `run_code` 第一次调用必超时——问题不在环境，而在启动协议。

- **握手重写**：不再调 `jupyter_client.wait_for_ready`。改为先订阅 iopub，
  再每 250 ms 换一个新 `msg_id` 重发 `kernel_info`；shell 回复与 iopub 第一声
  （`iopub_welcome` 或握手的 `status`）都到才算就绪，预算 20 s。
- **执行收口**：只认本轮执行自己的 `status:idle`；输出通道静默时会给一条明确警告，
  不再静默拖到 120 s。
- **R**：`Rterm` 与 `Rscript` 的 argv 规则相反（前者必须带 `--args`，后者必须不带），
  现在按实际启动器选；启动后预载 `stats/graphics/grDevices/datasets/methods`，
  不用再在单元格里手写 `library()`。
- **失败回收**：启动失败先杀内核进程再关通道。旧版每次失败会留一个孤儿内核，
  积累到 7 个时后续测试开始“间歇性失败”。
- **诊断**：内核 stderr 现在会被接住，失败时带出末尾 20 行；错误分得更细
  （程序不在 / 缺内核包 / 协议超时 / 一个字节都没输出），并说明用的是哪个解释器、
  从哪来的（设置 / `OMCP_PYTHON` / `.venv` / PATH）。

## 2. 界面：去掉“布局模式”

顶栏那个「对话为主 / 分析为主 / 专注 / 笔记本优先」下拉删掉了。

- 现在只剩两个开合按钮：`收起左栏` / `收起右坞`。
- 右坞收起后，右侧保留一条 40px 图标条（文件 / 笔记本 / 产物 / 运行），
  点哪个面板就以它展开——这就是“按需展开”。
- 右坞开/合状态会记住（`omcp.global.dock-open`）；重开保持上次的样子。
- 旧设置自动迁移：上次选「专注」→ 右坞仍收起；其余三种 → 展开，宽度不变。旧键随后删除。
- `Ctrl+1–4` 不再切布局（空出）；`Ctrl+B` / `Ctrl+J` / `Ctrl+Alt+1–4` 保留。

## 3. 产物：从占位变成账本

产物面板以前是一句“还没接入”。现在它回答一个问题：**这次运行产出了什么文件。**

- `write` / `edit` 产生的文件精确记录（账本在 `<工作区>/.omcp/artifacts.jsonl`）。
- `figures/` 与 `results/` 另外扫一遍，补上脚本写出来的文件。
- `bash` / `run_code` 写了什么无法枚举，会显示成「另有 N 次运行产出未知」——
  **不知道就说不知道**，不会画成“没有”。
- 账本里有、盘上没了的文件显示「已不存在」，条目保留，不静默删除。
- 面板支持按目录分组、类型徽标、路径过滤、「仅已失效」、刷新；点条目跳到文件预览。

## 4. 升级注意

1. 直接覆盖安装即可（appId 未变）。
2. 第一次打开后，`.omcp/` 下会多一个 `artifacts.jsonl`（只有几十字节到几 KB 起步）。
3. 旧 `omcp.global.layout-mode` 会在首次读取时被换算并删除，不需要手动清理。
4. 若你的 Python 解释器没有 `ipykernel`，第一次跑 `run_code` 会直接提示装包，
   而不是等 60 秒超时。
