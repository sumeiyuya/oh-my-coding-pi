02根因：两个断点，一个在发送，一个在历史

数据流画出来就清楚了：附件在输入框里是完整的，进入消息列表时被丢掉；历史恢复时 image block 又被 textOf 过滤。

图 2 · 两个断点。红色是必须补的；绿色是已经存在、不用重做的部分。纯文本模型的分支单独标出，避免把“历史不恢复”误认为 bug。
断点 1

发送时没带附件

// App.tsx ~1045
setMessages((prev) => [
  ...prev,
  { kind: "user", text, id: msgId }
]);

pendingAttachments 只进了 pendingUser（失败回填用），没有进消息。

断点 2

历史恢复只取文字

// tool-rebuild.ts ~126
const text = textOf(m.content);
if (text) out.push({ kind: "user", text });

textOf 只保留 type === "text"；image block 被过滤。

03三个方案：先修到哪一步

区别只有一个：历史恢复要不要覆盖“纯文本模型”。覆盖它，就需要额外的附件索引。

方案 A

只修发送时

消息里带上 attachments，气泡渲染缩略图。

覆盖：发送后立即显示
不覆盖：切换会话、重启、历史

改动最小，但用户会觉得“图还是丢了”

方案 B · 推荐

发送时 + 历史 image block

发送时带 attachments；历史恢复保留 image block。

覆盖：发送后、有图模型的切会话/重启
不覆盖：纯文本模型的历史

主流程完整，改动可控

方案 C

完整附件索引

发送时写 msgId + 附件路径到索引；历史按索引关联。

覆盖：包括纯文本模型的历史
代价：存储格式、清理、fork/queue 关联

等确认“纯文本历史必须恢复”再做

方案覆盖范围改动风险
A发送后当前会话App.tsx + CSS切会话后图片消失
BA + 有图模型的历史App.tsx + tool-rebuild.ts + CSS纯文本模型历史仍不显示
C全部（含纯文本模型）B + 附件索引/清理关联不稳、改动大

04方案 B：两条路都补上

发送时把附件放进消息；历史恢复时把 image block 留下来。两条路都指向同一个气泡渲染。

图 3 · 方案 B。绿色是发送路径，蓝色是历史路径；两者都产出同一种消息结构，渲染层只认 attachments。

数据结构

type UserImage = {
  id: string;
  data: string;      // base64
  mimeType: string;
};

// App.tsx 的 Msg
| { kind: "user"; text: string;
    attachments?: UserImage[];
    failed?: boolean; id?: string }

渲染

{m.attachments?.length ? (
  <div className="msg-attachments">
    {m.attachments.map((img) => (
      <button onClick={() => openPreview(img)}>
        <img src={`data:${img.mimeType};base64,${img.data}`} />
      </button>
    ))}
  </div>
) : null}
<div>{m.text}</div>

07验收：八条

  • 发送：附一张图发送，用户气泡立即显示 56px 缩略图，文字不被挤坏。
  • 多图：附 3–4 张，缩略图横向排列、满行换行，不撑破气泡。
  • 历史（有图模型）：切走再回来，图片仍在（getMessages 恢复）。
  • 纯文本模型：当前会话显示缩略图；模型收到转述；视觉服务未配有明确提示。
  • 失败：消息标“未送达”，输入框回填文字 + 图片。
  • 大图：点击缩略图打开应用内大图，可关闭。
  • 无图：原有纯文字消息排版不变。
  • 工程：typecheck、build 通过；现有附件上传测试不回归。

08风险与待确认

风险说明处理
base64 内存单张最大 4MB、最多 4 张；气泡直接渲染原图会解码整张先直接渲染；滚动卡再加 canvas 缩略图（160px）
历史体积pi 历史本身保存 image block；前端不额外持久化不在 .omcp 重复存 base64（除非做 C）
纯文本模型历史pi 历史只有转述文字，没有 image block本次接受“历史不显示”；需要则做 C
隐私原图已写入 <workspace>/.omcp/attachments/保持现有目录；后续可加清理策略
