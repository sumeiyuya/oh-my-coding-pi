01方案摘要：一句话与六条原则

先定分工，再谈实现。分工错了，后面每一行代码都会和 pi 的语义打架。

一句话：pi 已经是完整的 MCP 宿主；omcp 缺的不是协议，而是 DAWN 已经验证过的那套产品行为—— 配置怎么改、密钥放哪、状态怎么报、信任记在哪、只读工具怎么放行。
原则 01

协议层不重写

连接、工具发现、调用、重连、OAuth、结果截断全部由 pi 内置扩展完成。omcp 不引入 MCP 客户端依赖，也不自己起连接池。

原则 02

配置文件只写“名字”

mcp.json 里只出现变量名占位；值进 omcp 的 SecretStore。缺哪个变量，界面就点名说哪个。

原则 03

状态三态，失败必带原因

unchecked / ready / failed。未检查不等于失败；失败必须给出可执行的原因，而不是一句“连接失败”。

原则 04

信任按“名字 + 指纹”

信任存 omcp 自己的设置，不写进项目文件。同名但命令/URL 变了就是另一台，必须重新确认。

原则 05

只读工具要能被方案期放行

只读的 MCP 工具在只读模式与方案期应当可用；写工具不行。判据是服务器自己声明的 readOnlyHint。

原则 06

配置写入可回滚

写之前备份原文，写之后立刻读回校验；读不回来就写回原文并报错。用户的文件不是我们的数据库。

02架构：四条通道，各走各的

omcp 与 pi 之间只有四条通道。把它们画清楚，就不会在错误的地方写代码。

图 1 · 四条通道。配置（蓝）与密钥（青）由主进程写向 pi；状态（灰虚线）走独立子进程；审批（橙）由 pi 反向问主进程。MCP 服务器只和 pi 说话，omcp 不直接连。
通道 ① 配置

`<agentDir>/mcp.json`。omcp 是唯一写入者；写前备份，写后读回校验。

通道 ② 密钥

配置文件里只有 `${OMCP_MCP_…}`；值在 SecretStore，spawn 时注入。

通道 ③ 状态

`pi mcp list --json` 是权威；它是独立进程，不会污染当前会话。

03时序：从“粘贴一段 JSON”到“模型调到工具”

两条路径要分开看：配置路径决定“能不能用”，调用路径决定“能不能安全地用”。

图 2 · 两条路径。配置路径止于“工具已注册”；调用路径每次都要过审批。红色/橙色是安全边界，不能省。

04状态机：未检查 ≠ 失败

pi 只告诉我们“连上没连上”；omcp 要补的是“还没试过”和“配置变了”这两种真实状态。

图 3 · 状态机。只有 checking 是瞬态；ready / failed 都要带工具数或原因。stale 是 omcp 自己的状态，用来防止“界面显示连上了，其实配置已经改了”。
pi 的 stateomcp 视图规则
connected（或带 tools）ready工具数 > 0 才算 ready；工具为 0 时显示“连上了，但没有工具”
failedfailed直接把 error 透传；空 error 视为异常，标成“失败但没给原因”
disableddisabled不连接；保留条目，不算失败
（尚未调用检查）unchecked面板打开、保存配置后、重启后都回到这里
（检查子进程运行中）checking禁止并发检查；按钮变“检查中…”
（项目文件存在但未信任）note把 pi mcp list 返回的 note 原样显示，不说成“没有服务器”

05权限：只读能放行，写工具必须问

DAWN 把 readOnlyHint 一路接到了方案期门；omcp 现在只硬编码放行五个内置只读工具。

图 4 · 决策顺序。方案期先判，策略后判；只读 MCP 工具在方案期放行，依据是服务器声明的 annotations.readOnlyHint，不是工具名里有没有 get_ 这种猜测。
为什么只读标记必须由 pi 进程上报：主进程只能拿到 tool_call 的 toolName 和 input，拿不到 annotations。 所以要在 permission-ext 里于 session_start 时读 pi.getAllTools()，把 {name, readOnly, destructive} 上报给主进程缓存，供 PolicyService.decide() 使用。

授权粒度要改一次

现状问题改法
tools.allow 精确匹配任何 mcp__x__y 都落进 tool:unlisted支持 glob：mcp__fs__read_* 可单独白名单
授权按 ruleId 记忆允许一次 tool:unlisted，等于放行所有未列工具（包括新加的 MCP 工具）授权键带工具或服务器：tool:unlisted:mcp__fs
只读工具不在白名单只读模式下连 list_files 都拒annotations → 只读集合，只读模式与方案期放行
工具卡片只显示名字模型看到的 mcp__fs__read 在界面上不可读卡片显示 fs · read，参数摘要优先 query/path

06契约：类型、IPC、配置文件

先把类型定死，后面的实现才有验收对象。

共享类型（packages/shared/src/protocol.ts）

// 只放视图，不放密钥值
export type McpExposure = "direct" | "deferred" | "codemode" | "hidden";
export type McpState = "unchecked" | "checking" | "ready" | "failed" | "disabled";

export interface McpToolView {
  name: string;
  description?: string;
  readOnly?: boolean;
}

export interface McpServerView {
  name: string;
  transport: "stdio" | "http";
  command?: string;
  args: string[];
  url?: string;
  cwd?: string;
  /** 需要的环境变量名 / 请求头名；值不在视图里 */
  secrets: string[];
  missingSecrets: string[];
  enabled: boolean;
  exposure: McpExposure;
  description?: string;
  from: "global" | "project";
  /** command/args 或 url 的 sha256 前 16 位 */
  fingerprint: string;
  /** 存在应用设置 mcp.trusted.<name>.<fingerprint> */
  trusted: boolean;
  state: McpState;
  error?: string;
  tools: McpToolView[];
}

export interface McpListView {
  configPath: string;
  servers: McpServerView[];
  problems: string[];
  /** pi 的原话：项目未信任时说明 .pi/mcp.json 被忽略 */
  note?: string;
}

IPC（preload 暴露为 window.api）

channel入参出参 / 副作用
mcp:list—McpListView；只读，不启动服务器
mcp:check{ name?: string }更新状态；有副作用：会启动所有已启用服务器
mcp:save{ json: string, name?: string }{ name, needsSecrets }；抽走密钥值，写文件并重启 pi
mcp:remove{ name }McpListView；只删全局配置，项目文件不动
mcp:flag{ name, flag: "enabled"|"trusted", value, fingerprint? }McpListView；enabled 写文件，trusted 写应用设置
mcp:secret{ name, key, value }{ ok }；只写 SecretStore，不回显
mcp:open-config—用系统默认编辑器打开 mcp.json

配置文件长这样

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:/desktop/coding"],
      "env": {},
      "exposure": "direct",
      "description": "浏览与读取工作区文件"
    },
    "docs": {
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer ${OMCP_MCP_DOCS_AUTHORIZATION}" },
      "exposure": "deferred",
      "description": "检索内部文档"
    }
  }
}

文件里只出现 ${OMCP_MCP_<SERVER>_<VAR>}；值在 %APPDATA%/oh-my-coding-pi/secrets.json，键名 mcp:<server>:<VAR>。 启动 pi 与运行 pi mcp list 时都按同一张表注入环境变量。配置文件可以进 git，密钥不会。

写入流程（五步，失败可回滚）

1 · 备份

原文件复制为 mcp.json.bak，只保留一份。

2 · 改结构

解析 → 只改 mcpServers[name]，未知字段原样保留。

3 · 原子写

写 .tmp 再 rename，避免写一半。

4 · 读回校验

重新解析；名字、command/url、exposure 全部再验一遍。

5 · 失败回滚

写回原文，报出具体原因；界面不显示“已保存”。

6 · 重启 pi

复用插件开关的 supervisor.stop() → start()；提示“下一段新会话生效”。

空态与错误态要分开

  • 还没有配：给出配置路径 + 粘贴框，不说“加载失败”
  • 读不到名单：显示 JSON 解析错误的位置与原文
  • 项目文件被忽略：原样显示 pi 的 note，并给“打开信任项目”的入口
  • 连不上：原因 + stderr 尾部 + 缺哪个密钥，三者分开

交互纪律

  • “试一次”会启动进程，按钮旁必须有这句提示
  • 检查进行中禁止再次点击；同一时刻只跑一个子进程
  • 保存成功后不假装“已生效”，只说“重启 pi 后生效”
  • 密钥输入框 type=password；保存后只显示“已保存”，不回显

09验收：八条，逐条过

每一条都要有实际证据（截图、JSON 输出或审计行），不接受“应该可以”。

  • 添加：粘贴一段 filesystem 的 JSON → 保存 → 列表出现该服务器，状态从 unchecked 变 ready，工具数正确。
  • 调用：新会话里模型直接看到 mcp__filesystem__* 并成功调用一次；不出现“工具不存在”。
  • 审批：调用触发审批弹窗；点“拒绝”后模型收到明确拒绝原因，且服务器端没有收到该次调用。
  • 密钥：配置一台需要 env 的服务器，未填密钥时显示“还差 X”且连接失败；填上后 ready；mcp.json 里搜不到密钥明文。
  • 回滚：手工构造一个写坏的 JSON 场景（如非法 name），保存失败，文件内容与保存前逐字节一致。
  • 失败信息：把服务器命令改成不存在的路径，状态 failed，界面能看到 error 的最后几行，不是一个“连接失败”。
  • 信任：改掉某台服务器的命令，指纹变化；原来的“我信得过”失效，下次调用重新询问。
  • 只读：进入方案期，调用只读 MCP 工具被放行；调用写工具被 plan:readonly 拒绝。
边界也要验收：项目未信任时，.pi/mcp.json 不生效，界面显示 pi 的 note；
删除服务器只删全局配置，不动项目文件；
检查进行中重复点击不会起第二个进程。

10风险、边界与“不抄清单”

风险事实应对
stdio 服务器 = 任意代码pi 直接 spawn command；omcp 的审批门只管工具调用，管不到服务器内部新增时显示完整命令并要求勾选“我信任这个程序”；信任按指纹记录
远程 = 数据外发工具入参可能包含路径、查询词、文件片段远程服务器行固定标注“数据离开本机”；首次使用弹一次确认
检查有副作用pi mcp list 会启动所有启用的服务器只在打开面板/手动点“检查”时跑；按钮旁写明；串行加锁
项目配置看不到状态pi mcp list 在项目未信任时返回 note，不列项目服务器；它没有 --approve 参数默认只管理全局配置；信任项目时明确提示“项目服务器状态需在会话中验证”
上下文成本direct 会全量声明工具；服务器多时撑系统提示新服务器默认 direct；工具数 > 12 时 UI 建议改 deferred
会话与配置不同步改 mcp.json 要重启 pi 才生效保存后重启并提示“下一段新会话生效”；不假装已生效

不抄清单（DAWN 有，但 omcp 不该抄）

不抄 自建 MCP client 与连接池
pi 已有；重复实现会和 exposure、审批、结果截断脱节，且要自己维护重连与 OAuth。

不抄 legacy SSE 传输
pi 明确拒绝 SSE；遇到只给 SSE 的服务器，让用户换 /mcp 端点或放弃。

不抄 YAML 配置
mcp.json 是跨客户端通用格式，能直接吃 Claude/Cursor 的现成配置，这是优势。

不抄 server__tool 命名
pi 用 mcp__server__tool，已带命名空间；界面层做可读化即可，不改工具名。

不抄 全量直接注册工具
DAWN 把所有工具都塞给模型；omcp 用 pi 的 exposure，按服务器规模选 direct / deferred。

要抄 产品行为，不是实现
三态、缺密钥点名、试一次、信任按指纹、来源标注、写后回滚、只读贯通——这七条与协议无关，直接照做。
