## 一句话

**缺陷修复版，没有新功能。** 五条都是 0.7.0 发布后盘点出来的确定问题，每条都有代码位置与验收方式。

## 1. 子任务不再是绕过审批的后门（安全）

0.7.0 的 `subagent` 起子进程时只给 `--tools`，**不带审批门**——审批门是主进程按 `--extension` 注入的，子进程里没有它。于是名册写 `tools: bash, write` 的子 agent 可以直接跑命令、写文件，**不弹任何审批**。

修法（跟父会话权限档联动）：

| 父会话权限档 | 子任务拿到的工具 |
|---|---|
| 完全访问 `allow-all` | 名册要什么给什么 |
| 请求批准 / 自动拦截 / 只读 | 只给 `read` `grep` `find` `ls` `glob` |

- 名册没写 `tools` 时，只读档也**显式收紧**——不传 `--tools` 等于 pi 默认全套（含 bash/write），那才是最漏的一条。
- 被裁掉的工具写进工具结果：`[提示] 父会话不是完全访问档，子任务没有审批通道，已裁掉这些工具：bash, write`。模型不会以为自己能用。
- 父会话的权限档由子任务并发闸在领号时一并下发，不依赖环境变量快照（中途换档也生效）。

## 2. 浏览器插件的 15 个工具全部修好（功能）

`browser_open` / `browser_snapshot` / `browser_click` 等工具的 `execute` 用闭包生成，写成了 `async (p) => …`——而 pi 的第一个参数是 **toolCallId**。所以它们收到的是 `call_xxx` 字符串，参数全丢。

0.7.0 修过另外 17 个工具的同款错误，这一族是闭包写法，正则没扫到。现在补上了。

## 3. 审批卡告诉你「来自哪段对话」

0.7.0 把运行时标签条删掉后，审批卡上的来源显示退化成「后台 N」——这个 N 已经没有对应物了。现在显示**「工作区 / 会话标题」**，与侧栏一致。

## 4. 刚打开的会话不会被自己挤掉

三个会话同时开时，可能把**正在启动**的槽停掉，表现是"刚打开就挂起，再点一次才起来"。

原因是抢占判定只排除 `busy`，而启动中的槽 `isRunning=true`、`busy=false`——正好被挑中。现在排除 `starting`。

## 5. 清理

- 删掉已无入口的 `createRuntime` / `closeRuntime`（标签条移除后的遗留）。
- 挂起提示改成会话口径：「会话已挂起（空闲回收）；切回会自动恢复。」

## 冒烟脚本加强（`scripts/smoke-sessions.mjs`）

以后改并发相关代码可以直接重跑：

- **启动时等 pi 真正就绪**：固定 `sleep` 会把"还没启动完"误判成"模型不可用"（这一版发布前就踩到过一次）。
- **S7 换工作区**：用 `workspace:open` 切到临时目录（绕开原生选择框）→ 断言旧工作区的槽被收掉 → 切回。
- **S8 子任务闸**：新增只读 IPC `subagent:gate-state`，断言 空闲 `inUse=0` → 跑一轮 `inUse≥1` → 结束回 `0`。
- 新建会话后等它落盘；点击前等空闲，避免 disabled 元素把脚本卡死。

## 升级说明

覆盖安装即可。`OMCP_PLUGINS`、会话文件、`.omcp/`、审计与密钥位置都没变。

**行为变化**：只读/请求批准档下，子任务的写类工具会被裁掉。如果你的子 agent 名册里有 `tools: bash` 且确实要写文件，需要把父会话调到「完全访问」，或者等后续版本提供子任务的审批通道。
