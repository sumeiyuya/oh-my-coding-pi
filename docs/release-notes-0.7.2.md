## 一句话

**工作区不再是"模式"。** 一个工作区在跑任务时，你可以切到另一个工作区、打开它的会话、新建对话——切走的那个照常跑，切过去不再是重启进程。

## 1. 切工作区：从"重启"降级为"改指针"

旧实现切一次工作区要走七步：停默认槽 → 关掉**其他工作区**的槽 → 硬等 350 ms → 改写 5 个全局指针 → 冷启 pi → 渲染端 5 次串行重拉。这段时间里既没有可用槽（所以开不了新对话），被切走的工作区里正在跑的任务也一并被杀。

现在：

- `openWorkspace` 只改视图指针（工作区根 / 会话目录 / 状态文件），**不 stop 任何槽**；
- 默认槽同工作区直接复用；在别的工作区**且正忙就不动它**；只有空闲时才重新拉起；
- 本机实测（Windows，`logs/timings.jsonl`）：一次打开/切换 **25–60 ms**（原来固定 350 ms 起）。

## 2. 侧栏：按工作区分组，列出全部会话

- 展开任意工作区即列出它的会话（带标题与相对时间），点一条直接打开；
- 打开别的工作区的会话时，视图自动跟过去，文件树/工作区信息一起刷新；
- 原「切换到此工作区」按钮改为「**在此新建会话**」——新建的会话落在那个工作区，不需要先"切过去"；
- 每个槽有自己的 `--session-dir`，B 里新建的会话不会再写进 A 的目录。

## 3. 打开会话：历史先到，输入后解锁

- 一段会话可能要 spawn 一个 pi 并等它就绪（几秒）。旧做法是**等它回来再画**，点一下就是一段空白；
- 现在先画转录中枢里的快照（只读主进程内存），槽就绪后再用真内容接管；
- 打开期间输入框可打字但**发送被拦**（提示「这个会话还在连接」）——否则这句话会发给上一个会话。

## 4. 会话列表：异步 + 增量

`readdir / stat` 全部异步，按 `mtime + size` 判断，没变的文件只 stat；首行只读 4 KB；补标题移出热路径。

合成基准（400 个会话文件）：旧实现每次 **194 ms** 且阻塞主线程；新实现冷扫 198 ms（不阻塞）、热扫 **13 ms**。

## 5. 后台会话看得见

- 标签显示运行时长：当前标签 `3:12`，后台标签 `后台 · 3:12`（强调色）；
- 日额度按**档位**提醒：80% 与 100% 各一次（`E_BUDGET_NEAR` / `E_BUDGET_DAILY`），写明「来自当前会话 / 后台会话（文件名）」，并且**不会自动停槽**——停槽会丢掉正在飞的一轮。

## 6. 修复：别的会话在跑时，当前会话发不出消息

0.7.1 的 `submitPhase` 是**一个全局状态**。事件按会话分流，后台会话的 `agent_settled` 只进它自己的桶，于是全局值永远停在 `streaming`：切到另一个会话，发送按钮就是灰的，点了也没有任何提示。

- 阶段改为**按会话记账**，当前会话只看自己那一份；
- 发送门的判定抽成纯函数（排队 / 连接中 / 它自己上一轮没结束 / 槽在启动），每种拦截都有明确提示；
- 顺带修掉同族的三个串台：排队时锁定输入（原来能发，且会发给上一个会话）、失败回填只回填它自己那份、`send()` 一开始就固定目标会话（预检 await 期间切走也不会发错人）。

## 7. 行为变化与默认值

- **活跃槽上限默认 3**（设置里可调 1–4）。超过上限时挂起最久未用的空闲槽，等审批的槽不会被抢。
- 切工作区**不再停止后台**，所以后台会话会继续消耗额度——这是刻意的，标签上有计时与额度提醒。
- 关掉标签才会停止该会话的槽；会话文件始终保留，随时可重开。

## 升级说明

覆盖安装即可。会话文件、`.omcp/`、审计、密钥、插件开关都没变；`workspaces.json` 的格式也未变（新增了"最近工作区里列会话"的读取路径）。
