## 一句话

0.6.11 做到了「多个会话各跑一个 pi 进程」；**0.7.0 把这套东西补成了一套并发内核**：会话是身份、进程是可回收的槽、转写活在主进程、副作用按会话记账。并且第一次有了**子任务通道**。

## 1. 标签 = 会话，进程降为「槽」

之前标签栏写的是「默认 / 后台 1」——那是进程，不是对话。同一个进程换了会话，标签名字不变，而内核变量还跟着进程走。

- 标签栏改成会话级：标题、运行状态点、未读徽标、排队位次。
- 进程降为**槽**：一个槽同一时刻只绑一个会话，可以停、可以复用、可以换绑。
- **切标签不再因为「忙」被禁止**——每个会话有自己的槽，切走不停。
- 满员不再直接报错：空槽 → 挂起槽复用 → 新建 → 停最久未用的空闲槽 → 排队（显示位次）。

额度算的是**同时在跑的槽**，挂起的不占。默认 2 个，可配 1–4。

## 2. 转写搬进主进程（切走不停、刷新不丢）

会话内容不再只活在渲染进程的内存里：

- 主进程按会话维护转写与 `revision`，后台会话照样记录（只是不推给界面）。
- 切回会话时拿一份快照，工具卡片、流式文本、系统提示都在。
- F5 之后标签、未读、转写都还在。
- 未读由主进程算，切回自动清零。

## 3. 内核、预算、方案期、权限档、时序全部按会话

这一条修的是**数据串台**，不只是体验：

| 项 | 之前 | 现在 |
|---|---|---|
| 内核变量 | 跟进程走：会话 A 的 `df` 会出现在会话 B 里 | 跟会话走；关标签不销毁内核，10 分钟空闲回收并**明确告诉你变量已清空** |
| 预算 | 永远量默认会话：后台会话烧钱不拦，默认超限拦住所有会话 | 量发起的那段会话；日账仍是账号级 |
| 方案期 | 单对象：A 批准方案，B 也变成已批准只读 | 按会话记；A 的批准不影响 B，内容漂移只撤销那一段 |
| 权限档 | 全局一个值，切会话时是旧的 | 按会话现算（会话覆盖 > 应用默认） |
| 回合时序 | 全局一份，第二个会话直接不记 | 一个槽一份 |

## 4. 崩溃说得清、换工作区收得干净

- pi 进程崩了：有回合在飞 → 标签标红、转写里留一句「本轮的回复被中断了，可以直接重发」；空闲时崩溃 → 只留一句「已自动重启」。**主动停（回收/抢占/换工作区）不打扰你。**
- 崩溃后自动重启并恢复可用（此前渲染端会一直以为在忙，输入框卡在「追加」）。
- 换工作区时把这个工作区的后台槽全部收掉、旧队列丢弃。

## 5. 子任务通道（新）

模型可以把「读一堆文件只要结论」的活儿分出去，子任务跑在**独立的 pi 子进程**里，有自己的上下文窗口。

- 三种模式：single / parallel（一次 ≤8 个、同时 ≤4 个）/ chain（`{previous}` 引上一步）。
- 单个子任务墙钟 10 分钟、输出 50 KB 截断。
- 子 agent 名册：`<工作区>/.omcp/agents/*.md`（frontmatter：name / description / tools），项目级覆盖用户级。
- **全局并发闸**：名额是全局的，因为限流的是 provider。2 个槽 × 每槽 4 个子任务 = 8 个请求同时在飞，不挡就会整批 429。领不到名额会**明确拒绝**，不发出去也不偷偷超额。

开关在「设置 → 插件」里（默认关）。并发上限用 `OMCP_SUBAGENT_CONCURRENCY`（默认 4）。

## 升级说明

- 会话文件、`.omcp/` 目录、审计、密钥位置都没变，直接覆盖安装即可。
- 标签栏从「运行时」换成「会话」：之前打开的会话仍在侧栏，从中打开即可。
- 后台会话的 pi 进程现在以**工作区**为工作目录（此前后台槽误用了应用的启动目录，影响 `read`/`bash`/`grep` 的相对路径）。
- 内核的空闲回收从「跟着 runtime」改成「跟着会话」，默认 10 分钟（`OMCP_KERNEL_IDLE_MINUTES` 可调）。

## 已知限制

- 多窗口仍不支持（写入仲裁需要租约，未做）。
- MCP 工具在 `tools.allow` 之外时仍需逐次审批。
- `subagent` 的子进程继承父会话的 provider/model；子 agent 若在名册里指定了 `model`，以名册为准。
- 全局子任务闸的 429 路径有 HTTP 层测试，但没有在两个槽同时压满时实测。
