# 技能（Skills）

- 版本：0.5.0（P5.1）
- 日期：2026-11-13
- 位置：界面「技能」页；磁盘 `.agents/skills/<name>/SKILL.md`

---

## 1. 它是什么

技能是**可复用的分析方法**：一段写给模型的步骤说明，加上触发描述。模型在启动时看到所有技能的
`name` 与 `description`，判断该用哪个，再按需读取正文。

与 `AGENTS.md` 的分工：

| 文件 | 作用 | 范围 |
|---|---|---|
| `AGENTS.md` | 项目约定（目录、口径、禁忌） | 每个工作区一份，始终生效 |
| `.agents/skills/<name>/SKILL.md` | 可复用流程（描述统计、图件规范…） | 按需触发，可单独启停 |

---

## 2. 格式

```markdown
---
name: desc-stats
description: 按分组做描述统计并输出 CSV。用户说“描述统计”“分组汇总”时使用。
---

# 描述统计

1. 读取用户指定的数据文件。
2. 按分组计算 mean / median / count。
3. 打印表格。
4. 写到 `results/tables/desc-stats.csv`。
```

校验规则（技能页会直接标红）：

- 必须以 `---` 开头并有闭合的 `---`；
- `name`：小写字母、数字、连字符，≤ 64 字符；
- `description`：必填，≤ 1024 字符——模型靠它判断何时使用，写不清等于不会触发。

---

## 3. 怎么被加载

- 应用把 pi 的工作目录固定为工作区（ADR-035），pi 从 `<ws>/.agents/skills/` 发现技能。
- **项目级技能默认不加载**：设置页「信任本项目」未勾选时，应用给 pi 传 `--no-approve`（ADR-036）。
- 勾选后传 `--approve`，pi 在启动时读取并注入「name + description + 路径」的索引。
- 启停某个技能 = 把 `SKILL.md` 改名为 `SKILL.md.disabled`（pi 只认 `SKILL.md`），保存后自动重启 pi。

用户级技能（`%USERPROFILE%\.agents\skills\`）不受此开关影响，始终可见。

---

## 4. 审计

- 模型读取 `SKILL.md` 时，审计摘要写成 `skill:<name> · <路径>`；
- 调用 pi 的 `use_skill` 工具时同样标注；
- 启用/停用技能本身也落审计（`toolName: "skill"`，`scope: enable/disable`）。

注意：如果模型只看注入的 description 就照做、**没有读正文**，就不会产生技能级审计——这是信息边界，
不是漏记（见 `docs/known-limits.md`）。

---

## 5. 边界：不做在线安装

**只读本地目录，不做在线安装，也不校验来源。**

这不只是“还没做”，是刻意的：

- 在线安装会引入供应链与来源信任问题（DAWN 用 `.dawn-source.json` + commit 固定来解决，我们没有那套机制）；
- 技能正文是**指令**，从网上装的技能等于让陌生人往你的分析里塞步骤；
- 因此界面上不提供搜索/安装入口，文档也不暗示后续支持。

需要共享技能时，直接把目录拷进 `.agents/skills/`，并自己 review 过正文。

---

## 6. 安全口径

1. 技能**不放宽任何权限**：正文里出现的 `rm -rf` 等命令仍然走审批门。
2. 技能是**指令注入面**：项目里的 `SKILL.md` 如果来源不可信，可能诱导模型执行你不想要的操作；
   所以默认不加载项目技能。
3. 启用技能后，审计里能看到“谁在什么时候读了哪个技能”。
